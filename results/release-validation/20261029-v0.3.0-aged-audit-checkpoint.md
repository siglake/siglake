## Bounded replay

`aged_audit_marker_count_finishes_during_and_after_maintenance` builds 32
one-file audit commits on local Iceberg storage. It pauses the current-source
audit recluster inside its first catalog commit window, runs the exact
`count(*) ... where query = <marker>` shape while the maintenance transaction
is pending, releases the commit, checks that files were removed, and runs the
same count again. Both counts returned the marker's exact-one multiplicity. The
focused test completed in 1.13 seconds.

The replay rejects a process-local catalog or maintenance lock: the count
finishes while the rewrite is held before catalog update. It also gives
current source a failing-before regression, because f958's all-table
recluster never reaches `query_audit` and therefore never reaches the test's
commit rendezvous. The small local fixture did not reproduce the 30-second
latency. It does not prove whether the retained request was in cache refresh
or manifest planning, and it does not prove that #7308 alone is sufficient at
the released aged scale.
